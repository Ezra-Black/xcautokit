Get started

Install in seconds, the XcodeBuildMCP way

Add to ~/.cursor/mcp.json or project .cursor/mcp.json 
{
  "mcpServers": {
    "xcautokit": {
      "command": "npx",
      "args": ["-y", "xcautokit@latest", "mcp"]
    }
  }
}
Global CLI 
npm install -g xcautokit@latest
xcautokit doctor
xcautokit tools
xcautokit mcp

cd /Users/ezrablack/Developer/XCAutokit

Build guide

How to build and ship XCAutokit for other people

Build the Go binary

go build -o autokit . or npm run build:go. Output lands in dist/autokit-darwin-arm64 and ./autokit.

Expose the CLI entry

The npm bin is npm/bin/autokit.js. It spawns the native binary. Subcommands: mcp, tools, doctor, init, status.

Link or publish

For you: npm link. For others: publish the xcautokit package to npm, then they run npx -y xcautokit@latest mcp exactly like XcodeBuildMCP.

Prime agent projects

xcautokit init writes AGENTS.md and a project MCP snippet so agents know the ticket workflow and tool order.

Optional Xcode live backend

Xcode 26.3+, project open, Settings → Intelligence → Allow external agents. XCAutokit uses xcrun mcpbridge internally when present.

Claude era MCP

Compatible with modern MCP thinking

Tickets over sticky memory

Start tools return a ticket. Stop tools take that ticket back. Same idea as the new MCP “ticket is the key” model.

Any client, one command

stdio MCP stays the default for Cursor and Claude Code. No load balancer drama for local agent work.

Xcode as backend, XCAutokit as brand

We keep XCAutokit tool names. mcpbridge is an internal capability, not a second MCP you have to juggle.

FAQ

Questions before you install

How is this different from XcodeBuildMCP?

Same install shape (npx + CLI), first party XCAutokit surface, and an internal Xcode mcpbridge backend. No competitor MCP required in your config.

Do I need Node to run XCAutokit forever?

Node is the distribution wrapper. The engine is a Go binary. Homebrew style direct binary installs can ship later the same way.

What if I am still on Xcode 26.2?

XCAutokit still works. Build and test use xcodebuild. Upgrade to 26.3+ when you want live Issue Navigator, previews, and docs search.

What is a ticket?

A small handle like xca_rec_… returned by record_start or start_sim_log_cap. Pass it to the matching stop tool. That is the modern MCP state pattern.

Where do I open this page?

Open site/index.html in your browser from the XCAutokit repo. It is a local sales and build guide, not a public site yet.

What dependencies do agents need?

macOS, Xcode CLT, and axe on PATH for UI automation. Run xcautokit doctor to verify.
